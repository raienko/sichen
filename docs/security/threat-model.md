# Threat model

> What could go wrong, by STRIDE, across the parts of the system — and the control that answers each threat, or the risk accepted.

Last reviewed 2026-10-19. Review again when a trigger below happens, and at least before each store release (roadmap 19).

**Review triggers:** the first authenticated feature; a new data class in the [inventory](data-inventory.md); a new third-party SDK or embedded web page; a new API route; a change to the release pipeline.

## The system

| Part              | Trust boundary                                                                            |
| ----------------- | ----------------------------------------------------------------------------------------- |
| iOS / Android app | Runs on a device the user (or a thief, or malware) controls. Talks to the API over HTTPS. |
| Web app           | Runs in any browser; served by the app's own server (Expo Router server output).          |
| API routes        | `src/app/api`, public on the internet once the web build is deployed.                     |
| Backend API       | Separate service at `EXPO_PUBLIC_API_URL`; authorization is its job.                      |
| Embedded pages    | Third-party content in `WebView`, talking to the app over the bridge.                     |
| Incoming links    | Universal / app links and the custom scheme, from anyone.                                 |
| CI / release      | GitHub Actions, EAS; holds signing and store credentials.                                 |

## Threats

| #   | STRIDE                 | Threat                                                                                                                                  | Control                                                                                                                                                                 | Status                                                                                                  |
| --- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| T1  | Information disclosure | Device backup or a rooted device exposes stored data                                                                                    | Android backup off (SEC-01); MMKV encrypted with a Keychain/Keystore key (SEC-02); query cache opt-in (SEC-03)                                                          | Done                                                                                                    |
| T2  | Spoofing               | A token copied from a backup or iCloud Keychain signs in on another device                                                              | Device-only Keychain items (SEC-04)                                                                                                                                     | Done                                                                                                    |
| T3  | Information disclosure | Logs from a staging build print passwords or tokens                                                                                     | Logger compiled out of release; `redact` on every logged request/response (SEC-06)                                                                                      | Done                                                                                                    |
| T3a | Information disclosure | The access token is sent to another host through a `//host` URL or a caller's `baseURL`                                                 | Token only when the fully resolved URL matches the configured API origin; ambiguous URLs refused                                                                        | Done                                                                                                    |
| T4  | Spoofing / Tampering   | An embedded page navigates to a look-alike login, uses the bridge from a foreign origin, or receives app messages after navigating away | Exact-origin bridge; navigation allowlist, off-list opens in the system browser; no file access or new windows; web messages addressed to trusted origins only (SEC-07) | Done                                                                                                    |
| T5  | Tampering              | XSS or clickjacking against the web app                                                                                                 | CSP (report-only → enforce), `X-Frame-Options: DENY`, nosniff (SEC-05)                                                                                                  | Report-only; enforce once clean                                                                         |
| T6  | Information disclosure | Fingerprinting the server from public responses                                                                                         | `/api/health` returns `{ status }` only (SEC-08)                                                                                                                        | Done                                                                                                    |
| T7  | Elevation of privilege | An API route trusts client input or skips auth                                                                                          | Route rules in `src/app/api/index.md`: server-side auth, zod validation, generic errors (SEC-08)                                                                        | Rules in place; enforced in review                                                                      |
| T8  | Denial of service      | API routes abused once public                                                                                                           | Rate limiting at the host or middleware (SEC-08)                                                                                                                        | Open — with the first real route                                                                        |
| T9  | Spoofing               | A crafted deep link carries a token or drives a sensitive action                                                                        | `appLinkDomains` allowlist and one parse/route pipeline; no tokens in URLs (roadmap 09)                                                                                 | Partly; size/shape validation open                                                                      |
| T10 | Spoofing / Repudiation | Session theft or replay after sign-out                                                                                                  | Short-lived tokens, refresh, server revocation, awaited secure deletion (SEC-09)                                                                                        | Open — with auth                                                                                        |
| T11 | Information disclosure | Personal data visible in the app switcher or screenshots                                                                                | Screen privacy (SEC-10)                                                                                                                                                 | Open                                                                                                    |
| T12 | Information disclosure | Crash reports or analytics carry personal data                                                                                          | Scrubbing and consent (SEC-10)                                                                                                                                          | Open                                                                                                    |
| T13 | Tampering              | A compromised dependency or CI tool injects code                                                                                        | Exact pins, dependency review, weekly OSV scan (SEC-12), SHA-pinned actions, Maestro checksum (SEC-15), CODEOWNERS                                                      | Done; SBOM/provenance open (SEC-13/14)                                                                  |
| T14 | Information disclosure | A secret committed to the repository or the `EXPO_PUBLIC_*` bundle                                                                      | Secretlint in the hook and CI; every `EXPO_PUBLIC_*` value treated as public                                                                                            | Partly: no schema check for secret-shaped public vars yet; push protection is a GitHub setting (SEC-16) |
| T15 | Elevation of privilege | A fork's pull request reaches CI secrets                                                                                                | Read-only tokens; no secrets on untrusted PR code                                                                                                                       | Done                                                                                                    |
| T16 | Tampering              | A modified client calls the API                                                                                                         | Server-side authorization; attestation only if abuse appears (SEC-21)                                                                                                   | Accepted until a trigger                                                                                |
| T17 | Information disclosure | TLS interception on a hostile network                                                                                                   | HTTPS only, ATS on; pinning only with a documented threat (SEC-19)                                                                                                      | Accepted — platform TLS                                                                                 |

## Accepted risks

- **Web storage is readable by any script on the page.** The web keeps only Internal values in `localStorage`, and secrets in memory; an XSS would still read them while the page is open. CSP enforcement (T5) is the mitigation.
- **Rooted and jailbroken devices** can read memory and hook the app; encryption at rest protects data at rest only. No root detection until a fraud or DRM requirement (SEC-20).
- **iOS Keychain items outlive an uninstall.** The storage key may remain after the app is removed; it decrypts nothing once the MMKV files are gone.
